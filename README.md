# 个人相册（本机版）

这是只针对当前 Apple M1 Mac 构建的本地个人相册。

## 数据原则

- `nickname` 及其一级子文件夹是唯一文件夹规范。
- App 不创建、移动、重命名、复制或删除人物文件夹及其中媒体。
- 左侧“新建文件夹”是唯一例外：它只在 `nickname` 根目录创建一个空的直属子文件夹，等价于安全的 `mkdir`。
- 点击人物时，App 才递归读取对应文件夹，用于图片和视频预览。
- SQLite 只保存人物字段和明文文件夹路径。
- 每个人固定提供微信、QQ、X、TG、抖音五个平台；每个平台末尾的加号可增加一条记录。
- Finder 旧备注在导入时分类进入五个平台，App 不再保留或显示原 Finder 备注字段。
- 删除人物表示删除 SQLite 记录，不会删除文件夹。
- 新增或修正路径时，只接受 `nickname` 的直属子文件夹。
- App 禁止同时运行多个实例，避免并发编辑同一数据库。

## 默认位置

- 媒体库：首次运行时选择 `nickname` 文件夹；之后记住该路径。
- 数据库：`nickname` 上一级的 `个人相册.sqlite`
- 备份：`nickname` 上一级的 `个人相册数据库备份`

如果已保存的媒体库不存在，App 会要求重新选择 `nickname` 文件夹；数据库和备份仍放在所选文件夹的上一级。

## 备份

- 每次启动保存当前快照；字段写入或删除前后都使用 SQLite Online Backup API 创建一致性备份。
- 备份目录总量上限为 50 MiB。
- 超出上限后从最旧备份开始清理。
- 即使单个数据库已经大于 50 MiB，也至少保留最新一份备份。

## 构建

```sh
./Scripts/build_dmg.sh
```

产物位于 `dist/个人相册.app` 和 `dist/个人相册-本机版.dmg`。
